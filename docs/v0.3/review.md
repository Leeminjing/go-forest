# v0.3 独立审查

日期：2026-10-24。固定基线为 v0.2.0（`1161b62`），初次审查实现提交为 `07f2011`。Spec/Design 于 `d8bd6f1` 先行提交。两个独立审查者分别检查 Standards 与 Spec，修复后再次检查工作区及回归测试。

## Standards

初次发现 3 项 P2，均属于 [Design](design.md) 的明确约定，未追加启发式 smell 建议：

1. TLS 顶层配置加固没有覆盖 GetConfigForClient 返回值。审查者用真实连接复现，未启用 AllowInsecure 仍可协商 TLS 1.0，违反最低 TLS 1.2 要求。
2. 非 200 状态和错误路由统一返回 ErrContractMismatch，违反无效响应应报告协议错误的约定。
3. 本地 JSON 编解码失败丢弃原始 cause，无法通过 errors.As 检查 UnsupportedTypeError 等错误。

修复：使用统一 TLS 配置复制和加固路径，覆盖每个回调返回值；非法状态/路由与契约差异分别分类；本地编解码错误同时保留 sentinel 与原始 cause。静态证书链、附属字节、信任池和算法列表另行复制，私钥对象及回调继续由应用管理并在 Design 明确说明。

复核结论：三项均已修复，相关公开 API 回归连续三次通过，无剩余行动项。审查者未自行运行全量 race；主实施流程的最终 race 结果见 [validation.md](validation.md)。

## Spec

初次发现 1 项明确偏差：非法 HTTP 状态/路由误报为契约不兼容，与上述 Standards 第二项重合。TLS 静态配置浅拷贝作为所有权边界候选提出，未将其宣称为已演示攻击。

审查确认两个真实进程的业务调用走 TCP，取消、热替换、Kill 和同地址恢复有实际测试证据，Core 未改动。审查者运行桥接包测试通过。

复核结论：错误分类及 cause 符合 Design；TLS 静态配置隔离、动态配置安全限制和应用所有权均已明确，真实 TLS 回归通过，无新增发现或范围扩张。

初次结果：Standards 3 项、Spec 1 项；修复复核结果：两轴均无剩余行动项。

后续 CI 发现重启测试的时序假设过强，修正为允许旧空闲连接首次返回 unavailable，再由新的显式调用检查新契约，维持桥接无自动重试的设计。该调整只涉及测试和行为说明，不修改运行时。
